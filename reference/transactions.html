事务与视图

来源：Palantir Docs · Datasets（2026-10-20 核对）。配套课程：第 1 课。

一句话

数据集 = 后端文件系统里一组文件的包装；文件只能通过事务改变；视图 = 某分支、某时间点实际有效的文件。

事务状态

OPEN正在写文件
COMMITTED写入的文件进入视图
ABORTED写入的文件被忽略

事务类型

类型加文件改已有文件移除文件效果
SNAPSHOT✓—全部整体替换视图
APPEND✓✗✗只加新文件
UPDATE✓✓✗加文件，可覆盖 A → A′
DELETE✗✗✓从视图移除，物理文件仍在

视图算法

  1. 找到该时间点之前最近的已提交 SNAPSHOT（没有就从第一个事务开始）。
  2. 按顺序应用之后每个已提交事务，跳过 ABORTED。

官方例子

SNAPSHOT {A, B} → APPEND C → UPDATE A→A′ → DELETE B ⇒ 视图 A'C

坑

  • DELETE 不释放存储；物理删除靠保留策略（Retention）。
  • 视图绑定分支和时间点，脱离这两者谈"数据集里有什么"没有意义。
  • Data Integration 里还有一个大写的 "View" 产品概念（读时 union 多个数据集），和这里的"数据集视图"不是一回事。
