增量与快照

来源：Palantir Docs · Incremental usage guide（2026-10-27 核对）。配套课程：第 4 课。

判断顺序

  1. 输入没新事务、代码没变 → 新鲜，不跑（构建层面的规则）。
  2. 输出从没构建过，或 semantic_version 改了 → 快照。
  3. 非 snapshot 输入出现 SNAPSHOT / 覆盖文件的 UPDATE / 用户 DELETE / 未允许的保留策略 DELETE → 快照；若 require_incremental=True 则失败。
  4. 否则 → 增量。

读写模式

模式增量运行快照运行
added（默认读）上次运行后新增的行全部数据
current这次的全部输入这次的全部输入
previous上次运行时的全部输入空 DataFrame
输出默认写modify（追加）replace（整体替换）

装饰器参数

semantic_version默认 1；改了强制下一次非增量
require_incremental不能增量就失败（首次构建、改 semantic_version 除外）
allow_retention保留策略删除文件不破坏增量
snapshot_inputs声明某些输入可整体重写而不破坏增量

一句话

增量的前提是输入"只往后追加"。旧数据被换、被改、被删，就只能从头算。
