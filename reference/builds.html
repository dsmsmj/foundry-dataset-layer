构建与新鲜度

来源：Palantir Docs · Builds（2026-10-26 核对）。配套课程：第 3 课。

名词

Build计算数据集新版本（在输出上提交新事务）的机制，由多个 Job 组成
Job共享同一份逻辑的工作单元；多输出 Job 的输出总是一起更新
JobSpecJob 的构造定义：输入（InputSpec）+ 逻辑；改转换逻辑时发布

生命周期

  1. 解析：查环 → 查输入存在与 schema → 在输出上开事务（build locking）→ 可能排队
  2. 执行：Job 失败 → 直接依赖的 Job 与输出事务被终止；已完成的 Job 可能已写入输出

新鲜度

  • 输入数据集与 JobSpec 逻辑自上次构建以来都没变 → fresh，不重算。
  • force build：全部重算，不看新鲜度。
  • 推论：上游重算产出新事务 → 下游输入变了 → 下游也要重算。变化顺着依赖往下传。

Job 状态

WAITING → RUN_PENDING → RUNNING → COMPLETED / FAILED；被终止时 ABORT_PENDING → ABORTED（用户取消，或依赖的 Job 失败）。
